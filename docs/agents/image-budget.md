# 会话里的图片预算

智能体用读图工具打开一张图片，这张图片就会一直留在会话上下文里，后面每一轮请求都要把它再发一次。图片一多一大，请求会超时，模型服务这时只会报「The model you've selected is temporarily unavailable」，看起来像模型故障。EURO-23 上全栈工程师在 10-14 当天连续 7 轮失败，原因就是这个：会话里积累了太多参照图和 Playwright 截图。

## 规则（所有角色）

- **能不看就不看。** 截图只是要附到 PR 或评论里时，直接用路径上传（`multica issue comment add --attachment <文件>`、PR 正文里的链接），不要先用读图工具打开。
- **看之前先缩小。** 要看的图片先转成长边不超过 1280px 的 JPEG（质量 80 左右），单张不超过 300KB，再打开。不要直接打开 1440/1920 宽的原始 PNG，也不要打开整页长截图。只关心局部时，先裁出那一块。
- **一个会话最多看 6 张。** 包括参照图和自己的截图。超过的话，用脚本对比（尺寸、像素差、DOM 和计算样式），只把结论写进会话，不要把图片读进来。
- **同一张图不看第二遍。** 第一次看的时候就把需要的结论（尺寸、颜色、间距、差异）记成文字。
- **对比参照图优先用数据。** 布局和尺寸用 Playwright 读取元素的 `boundingBox()` 和 `getComputedStyle`，和参照图里量出的数字比，而不是来回看两张图。

## 出现「模型暂时不可用」时

- 同一个任务上连续 2 轮都在几分钟内报这个错，先怀疑会话太大，不要原样重试。
- 执行者：在评论里写明会话里大概打开过几张图片，交回队长。
- 队长：不要再在同一个会话里 @ 成员原样重派，这只会继续失败。先想办法让成员从干净的会话开始；做不到（或不确定能不能做到）就写「需要人类确认」，请维护者在 Multica 界面上处理。重新派活时，在评论里提醒对方遵守本文的规则。
