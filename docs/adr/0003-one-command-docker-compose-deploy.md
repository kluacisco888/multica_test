# 部署：单机 docker compose 一键部署，不依赖云服务

整个应用（前端、后端、PostgreSQL 和所需的数据目录）都用一个 `docker compose` 项目运行，一条命令就能起来。先部署在开发机上，验收通过后原样迁到维护者自己的本地服务器。之后对外访问由维护者自己在前面加 CloudFront。所以应用不能依赖任何托管云服务，例如 RDS、S3、SES。附件存在挂载卷里，所有配置都通过 `.env` 注入。

## Consequences

- 开发机上已经运行了 Multica 自己的容器（占用 127.0.0.1:3000、127.0.0.1:8080 和一个 postgres 容器），系统 nginx 占用了 80 端口。本应用要用独立的 compose 项目名、独立的数据库容器和数据卷，对外端口通过 `.env` 配置，默认值不能和上面这些冲突。
- 迁移到新服务器时，只需要复制 `.env`，再备份和恢复数据卷。需要提供备份和恢复脚本。
- 应用要能部署在反向代理或 CloudFront 后面，正确处理 `X-Forwarded-*` 头，并且外部访问地址可配置。
